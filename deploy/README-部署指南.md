### 三层防火墙（排障必读，2026-09-21 实战教训）

这台服务器对外服务的端口要过**三层**，任何一层没放行都不通：

| 层 | 位置 | 检查方式 |
|---|---|---|
| ① 应用监听 | 服务器内 `ss -tlnp \| grep <端口>` | 必须看到 LISTEN 行 |
| ② 阿里云控制台防火墙 | 控制台 → 实例 → 防火墙 | 规则"已启用" |
| ③ **服务器内层 ufw**（宝塔管理，Status: active） | `ssh root@... "ufw status"` | 列表里要有该端口；加规则 `ufw allow 8081/tcp` |

**教训**：当年部署银行项目时 ufw 放行了 8080（所以 8080 一直通），秒杀系统用 8081 时
只放通了②没放③，排查了一圈才定位到。**新端口上线三处都要放。**

当前已放行端口：20/21/22/80/443/888/8888/23403/39000-40000/8080/8081。

### 登录三步（Windows 自带 SSH，无需装任何东西）

1. `Win + R` → 输入 `powershell` → 回车
2. 执行：
   ```
   ssh root@8.133.222.0
   ```
3. **输密码** —— ⚠️ 两个新手最容易卡住的点：
   - 第一次连接会问 `Are you sure you want to continue connecting (yes/no)?` → 输 `yes` 回车
   - **输密码时屏幕上什么都不显示**（没有星号、没有圆点、光标不动）——
     这是 Linux 的安全设计，不是键盘坏了。**盲打完密码直接回车**即可。
4. 登录成功的标志：命令行提示符变成 `root@iZ......Z:~#` 这样的样子。

### ⚠️ 常见报错对照表（卡住先看这里）

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| `'xxx' 不是内部或外部命令，也不是可运行的程序`（xxx 是你密码的一部分） | **密码输在了命令提示符里**。`C:\Users\...>` 是 Windows 在等命令，不是在等密码 | 回车后重新执行 `ssh root@8.133.222.0`，等出现 `password:` 提示再输密码 |
| `ssh : 无法将...识别为 cmdlet`（PowerShell 措辞） | 同上，PowerShell 版的同一错误 | 同上 |
| `root@8.133.222.0's password:` 后输了密码又退回来，连报 3 次 `Permission denied` | 密码错了（或键盘大小写/中英文状态不对） | 等 1 分钟重试；输密码前确认输入法是英文、没开大写锁定 |
| **`Permission denied (publickey).`（没有 `password:` 提示）** | **服务器只收密钥、不收密码**（括号里列出它接受的方式）。绑过密钥对的服务器会禁用密码登录 | 走下方「密钥登录配置」，把自己的公钥导入阿里云绑定即可 |
| 连接超时 `Connection timed out` | 服务器没开机 / IP 不对 / 本地网络问题 | 阿里云控制台确认实例运行中；换手机热点试试 |

**核心概念**：终端里「`C:\Users\xxx>` 这样以盘符路径结尾的行」是 **Windows 的命令提示符**，
在这里只能输命令；只有先运行 `ssh ...` 并看到 `password:` 字样后，输入的东西才会被当成密码。
SSH 密码阶段**没有任何可见反馈**，输完直接回车即可，不需要确认。

### 密钥登录配置（服务器报 `Permission denied (publickey)` 时走这里）

> 原理：SSH 密钥是一对——`id_rsa` 是**私钥**（留在你电脑，绝不能外传），
> `id_rsa.pub` 是**公钥**（可以随便给别人，泄露无风险）。
> 服务器上存了谁的公钥，谁就能登录。你要做的就是把本机公钥登记到阿里云。

**方案 A（首选）：把本机公钥导入阿里云**

1. 获取公钥内容（`.pub` 文件双击打不开是正常的——Windows 不认识这个扩展名，文件没坏）：
   ```powershell
   # 直接显示内容，手动全选复制
   Get-Content C:\Users\<你的用户名>\.ssh\id_rsa.pub
   # 或一步到位：直接复制到剪贴板
   Get-Content C:\Users\<你的用户名>\.ssh\id_rsa.pub | clip
   ```
   也可以右键文件 → 打开方式 → 记事本（别双击）。
   要复制的是 `ssh-rsa AAAA....` 开头、邮箱结尾的**一整行**。
2. 浏览器打开阿里云**轻量应用服务器控制台**（swas.console.aliyun.com）→ 左侧菜单「**密钥对**」
   →「**导入密钥对**」：
   - 名称：`seckill-key`（随便起）
   - 公钥内容：粘贴刚复制的整行
3. 导入后，在密钥对列表点「**绑定密钥对**」→ 勾选 8.133.222.0 这台实例 → 确认。
   阿里云会提示**重启实例**，同意（约 1 分钟，期间 8080 网站短暂不可访问，无妨）。
   > 若列表里已有一个旧密钥对（当初配的），绑定新密钥对会**替换**它——正常，绑定后旧的失效。
4. 回到 PowerShell：`ssh root@8.133.222.0`
   → **这次不问密码，直接进入**（提示符变 `root@iZ...:~#`）。

**方案 B（控制台没有「导入」按钮时）：让阿里云现场生成一对**

1. 「密钥对」→「创建密钥对」→ 自动生成 → 浏览器会**下载一个 .pem 私钥文件**
   （⚠️ 只下载这一次，丢了就得删掉重来，妥善保存）。
2. 绑定到实例（同方案 A 第 3 步，会重启）。
3. 登录命令带上私钥：
   ```
   ssh -i C:\Users\<你的用户名>\Downloads\密钥文件名.pem root@8.133.222.0
   ```
4. 若报 `UNPROTECTED PRIVATE KEY FILE`（Windows 权限太开放），先修权限再连：
   ```powershell
   icacls "C:\Users\<你的用户名>\Downloads\密钥文件名.pem" /inheritance:r /grant:r "$env:USERNAME:R"
   ```

**方案 C（顺手可试，别指望）**：控制台「重置密码」→ 重启 → 再试密码登录。
只有当"禁用密码"是绑定密钥对造成、且控制台顺带放开密码时才生效——大概率依然 `publickey` 被拒，所以别把它当主路径。

**配好密钥的额外好处**：后续部署上传 jar 的 `scp` 命令也走同一套密钥，**全程不用输密码**。

### 密码忘了怎么办

阿里云控制台 → 轻量应用服务器 → 实例详情 → **重置密码** →
按提示**重启实例**后新密码生效（重置本身不生效，必须重启）。

### 不想用本地 SSH？

阿里云控制台的实例卡片上有 **「远程连接」** 按钮（Workbench 网页终端），
浏览器里直接开一个终端，不走本地 ssh，密码规则相同。

## ⚠️ 一、先读这段：关于服务器登录信息

**不要把服务器 root 密码发在聊天记录里。** 一旦发出，它会留在对话历史、日志、剪贴板里，
而且很多人这个密码是复用的（比如和邮箱、其他平台相同）。

### 三个更安全的选择（按推荐度排序）

| 方式 | 怎么做 | 安全性 |
|---|---|---|
| **① 你自己执行（最推荐）** | 我把命令都写好，你复制粘贴到服务器终端。我不接触你的服务器 | 最高 |
| **② 临时改密码** | 你改一个新密码发我，部署完立刻改回去，并检查登录日志 | 中 |
| **③ 用密钥登录** | 阿里云控制台可以生成密钥对；比密码安全，但配置稍麻烦 | 高 |

本项目的部署步骤已经脚本化（`deploy/deploy.sh`），**你自己跑一遍只需要 3 条命令**，
我建议走方式 ①。

## 三、部署步骤（方式 ①，你自己执行）

### 第 1 步：本地打包并上传

在**你的 Windows 电脑**上（Git Bash）：

```bash
cd "C:/Users/谁知青杉/WorkBuddy/2026-09-18-09-07-45/projects/seckill-system"

# 打包（用项目自带的 mvnbuild.bat 包装脚本）
# 注意：如果本地应用正在运行，先停掉，否则 jar 被锁无法覆盖
cmd //c "C:\Users\<你的用户名>\tools\mvnbuild.bat" clean package -DskipTests

# 上传到服务器（把 <IP> 换成你的服务器 IP）
scp target/seckill-system-1.0.0.jar root@<IP>:/opt/seckill/
scp deploy/deploy.sh root@<IP>:/opt/seckill/
```

> 如果 `/opt/seckill/` 不存在，先执行 `ssh root@<IP> "mkdir -p /opt/seckill"`

### 第 2 步：服务器上执行部署脚本

```bash
ssh root@<IP>
cd /opt/seckill
chmod +x deploy.sh
bash deploy.sh
```

脚本会自动完成：环境检查 → 端口检查 → 停止旧实例 → 后台启动（8081）→ 健康检查。

### 第 3 步：放行安全组端口

阿里云控制台 → 轻量应用服务器 → 你的实例 → **防火墙** → 添加规则：

```
应用类型: 自定义
协议:     TCP
端口范围: 8081
备注:     秒杀系统演示
```

**这一步不做，公网就访问不到**（最常见的部署失败原因）。

## 五、部署后的注意事项

### 1. demo profile 的数据是临时的

应用使用 **H2 内存数据库**，**重启后所有订单和库存数据都会重置**。
这对演示来说其实是优点（每次都是干净状态），但你要知道：

- 访问者看到的是重置后的全新状态，库存充足
- 如果想让数据持久化，需要切换 `application.yml` 中的数据库配置到 MySQL

### 2. 演示前先预热

应用启动后库存需要预热到 Redis，脚本已自动处理；
如果手动重启，记得调一次：

```bash
curl -X POST http://localhost:8081/admin/warmup/all
```

### 3. 服务器资源占用

`-Xms256m -Xmx512m`，对轻量应用服务器（通常 2G 内存）很友好，
与银行项目（8080）可以并存。如果服务器内存紧张（1G 以下），
两个 Java 应用同时跑会比较吃力，建议错峰演示。

### 4. 演示链接的有效性

部署成功后，线上演示入口才可用：

```
线上演示：http://<IP>:8081（账号：zhangsan/123456）
```

**投递前务必重新访问一次确认可访问。** 服务器到期、实例停机都会让链接失效。

## 六、可选：绑定域名 + Nginx 反代（进阶）

如果想让链接更好看（比如 `http://seckill.你的域名.com`），可以：

1. 买一个便宜域名并解析到服务器 IP
2. 用 Nginx 反代 8081：

```nginx
server {
    listen 80;
    server_name seckill.example.com;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

3. `nginx -t && systemctl reload nginx`

> 服务器 80 端口目前返回 403，说明已有 Nginx 在跑，可以在此基础上添加配置。
> 这属于加分项，不是必须——**先把 8081 直连跑通更重要**。

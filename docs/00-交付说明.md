## 三、你本机的环境问题（已全部处理）

### 问题 1：Maven 中文路径 → 改用直调 java

**根因**：`mvn.cmd` 依赖 `JAVA_HOME`，而工具沙箱会污染该变量；同时 `cygpath` 在转换
中文路径（`C:\Users\谁知青杉\...`）时编码错乱，classpath 失效。

**处理**：不用 `mvn.cmd`，改为直接用 `java -cp` 调 Maven 的 classworlds launcher，
全部使用绝对 Windows 路径。命令见 `README.md` 2.2 节。
（`tools\mvnbuild.bat` 已实测无效，勿用。）

### 问题 2：Lombok 与 JDK 25 不兼容

**根因**：Spring Boot 3.2.5 默认 Lombok 1.18.32 不支持 JDK 23+，注解处理器不运行，
报大量「找不到符号 getXxx/setXxx」。

**处理**（`pom.xml`）：
- 显式指定 `<lombok.version>1.18.40</lombok.version>`
- `maven-compiler-plugin` 中声明 `annotationProcessorPaths`

### 问题 3：Sentinel `eager: true` 导致 Tomcat 端口漂移

**根因**：沙箱内主机名无法解析，Sentinel 提前初始化失败，Tomcat 随机挑选端口（实测 51065）。

**处理**：启动参数加 `--server.port=8080 --spring.cloud.sentinel.eager=false`。

### 问题 4（最隐蔽）：Lua 参数被 JSON 序列化器加引号

**症状**：`redis-cli --eval` 跑同一个脚本完全正常，`redisTemplate.execute()` 报
`Lua redis() command arguments must be strings or integers`
→ 修掉后又报 `bad argument #1 to 'floor' (number expected, got nil)`。

**根因**：`redisTemplate.execute(script, keys, args)` 的 args 会经过
`Jackson2JsonRedisSerializer`，字符串被写成 `"86475"`（**带字面双引号**），
`tonumber('"86475"')` → nil。

**处理**：所有 Lua 脚本加 `sanitize()` 剥离成对的外层引号。

## 六、面试时可以这样介绍这个项目

> 这是我为了深入理解高并发场景做的一个秒杀系统。
>
> 秒杀的核心矛盾是瞬时流量和系统承载能力差两个数量级，所以我的整体思路是
> **层层过滤 + 异步削峰 + 多重兜底**：用幂等 Token 和限流挡掉大部分无效请求，
> 用 Redis Lua 脚本原子扣减库存作为性能核心，再用数据库条件更新做可靠性底线。
>
> 我在设计时特别关注了两件事：
> 第一，**不能信任任何单点**。所以即使 Redis 是性能核心，正确性仍然由数据库唯一索引
> 和条件更新保证 —— 因为 Redis 在主从切换、运维误操作等场景下都可能失效。
>
> 第二，**异常路径比正常路径更需要设计**。我在自测"重复下单"时发现库存被扣了但订单没生成，
> 才意识到每一条异常分支都要考虑库存回滚。我把一人一单校验提前到扣库存之前，
> 让这条分支根本不产生补偿需求，再用延迟消息 + 定时任务 + 对账三层保障。
>
> 压测上，我用自研的多线程压测程序做过验证：200 个用户抢 99 件库存，
> 最终 Redis 库存精确归 0，业务失败 100 笔（库存不足）+ 1 笔（重复下单），
> **系统异常 0 笔、超卖 0 笔**，账目 99+100+1=200 完全对得上。
> 不过压测机和被测服务同机部署，所以这个 QPS 是相对值，趋势可信但不代表生产环境。
